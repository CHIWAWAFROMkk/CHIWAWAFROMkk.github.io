# 校园外卖平台：数据库设计与 SQL 分析

## 运行
Node.js 20.11 或以上版本。在解压后的目录执行 `node verify.mjs`。
也可用 SQLite 打开 campus.sqlite，或在空数据库执行 init.sql。
sql.js 1.14.2 的 JavaScript、WebAssembly 与 MIT 许可证随包提供，无须在线安装依赖。

## 数据
4 家商户、12 名学生、12 道菜、96 笔合成订单。日期为 2024 年 4 月，服务于业务规则与查询验证，不含真实学生信息。刷新网页会恢复初始数据；下载当前数据库可保存本次演示。

## 表与规则
students、merchants、dishes、orders、order_items、payments、deliveries、refunds 共八张表。
金额使用整数分。订单明细保留成交价格快照。两组复合外键拒绝跨商家明细。支付与退款按订单唯一，避免重复入账。

## 下单事务
BEGIN IMMEDIATE → 创建订单 → 明细与扣库存 → 支付登记 → 配送记录 → COMMIT。
无效学生、库存不足或支付金额不一致触发 ROLLBACK。演示下单选择一种菜品，可购买 1–20 份；关系模型支持同商家的多菜明细。

## 退款事务
未送达的已支付订单支持全额取消。退款触发器核对支付金额、把状态改为 refunded 并恢复库存；唯一订单键和状态校验阻止重复退款。已送达订单不走取消流程。

## 查询口径
- 商家净收款 = 支付金额 − 全额退款金额；按订单粒度连接，避免多菜重复计算。
- 菜品销量排除退款，使用成交价。DENSE_RANK 计算商家内排名。
- 复购 = 区间内非退款订单至少两笔的学生 / 区间购买学生，不是留存率。
- 配送时长 = 送达时间 − 下单时间，只分析 delivered，超过 40 分钟为超时。
- 账实核对比较订单金额、明细汇总与支付金额，正常输出零行。
- 学生 + 时间、商家 + 时间建立复合索引，EXPLAIN QUERY PLAN 可查看访问路径。

## 工程实现
同一 delivery-core.mjs 支撑页面演示和本地验证。sql.js 在 Web Worker 中运行，编辑器在数据库副本执行，不影响订单数据。超过 3 秒终止 Worker 并恢复最近成功提交的快照；查询最多显示 500 行。数据在浏览器内存处理，不上传，不调用支付服务。

## 设计过程与讲述
先拆出学生、商户、菜品等实体，再用订单明细连接订单与菜品；随后从同店、金额、库存、幂等取消四条规则倒推约束与事务；最后将净收款、销量、复购和配送问题落成 SQL，并通过边界用例验证。

面试讲述可围绕一次失败下单展开：库存不足时，明细触发器抛错，外层事务回滚，订单和支付都不留下孤立记录。再展示一次成功下单和取消，观察库存恢复与账实核对结果。
