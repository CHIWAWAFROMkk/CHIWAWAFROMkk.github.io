# PEOPLE. RECORDS. IN ORDER.
丹纳赫实习场景 · HR 员工电子档案补录

约 6000 名员工的档案维护，真正的问题不是读出一份 PDF，而是让每一份资料回到正确的员工名下。

我先利用 OpenClaw 调用 DeepSeek 与 GPT API，制作初级版本；再将业务规则整理为面向外企 Microsoft 365 环境的迭代方案。

## 从模型调用，到业务闭环。
初版实践
### OpenClaw + DeepSeek / GPT API
用 OpenClaw 编排模型调用，围绕电子档案的信息提取与补录需求制作初级版本。

业务梳理聚焦三个问题：文件顺序不能代表员工顺序；没有档案不等于字段缺失；识别出的内容不能直接覆盖主数据。

关注点：模型调用与档案补录任务的结合。

企业版架构方案
### Microsoft 365
保留 Excel 主名单，以 SharePoint 承接队列与审核；由 Power Automate 调度匹配、提取和写回。

将身份核验、人工确认、断点续跑与审计放进流程。模型负责提供候选信息，写回由规则和审核控制。

关注点：受控数据流、权限、审核与可追踪性。

## 先读取员工， 再查找档案。
Excel 是 Master Data。PDF、JPG、PNG 是 Source Data。任务数量与处理顺序由花名册决定，档案目录只提供查找依据。

Excel 原始顺序工号与姓名候选档案身份与字段核验HR 审核补写空白字段

## 四条流程，各司其职。

### 建立任务
读取花名册 → 固定原始序号 → 校验唯一工号 → 按员工建立持久化队列。

入口：手动启动一个批次。每个员工只有一个对应任务。

### 匹配与提取
按队列序号取员工 → 文件名工号 → 文件名姓名 → 文本 / OCR → 身份确认 → 生成字段候选。

缓存按文件版本复用，文件列表不创建员工任务。

### 审核与写回
HR 逐项确认 → 重读主数据 → 比较旧值 → 仅写空白 → 回读核对 → 登记写入凭据。

一条写入通道；未批准的候选不进入正式花名册。

### 汇总与续跑
恢复中断任务 → 输出异常、无档案与已完成清单 → 按原始序号合并结果。

业务状态与系统错误分开，失败不会伪装成没有档案。

## 四种结果，不再混淆。
档案状态 | 判断依据 | 处理结果 | 

未找到电子档案 | 已完成查找，且不存在尚未排除的身份候选 | 进入无档案名单，不用“/”代替状态 | 

档案存在-信息缺失 | 身份确认、内容可读，资料未提供所需字段 | 记录具体缺失字段，其他候选仍可审核 | 

档案存在-识别失败 | 档案归属已确认，相关内容模糊或无法读取 | 标明页码与识别问题，转人工处理 | 

已完成 | 必需字段有依据，审核及写回核对均完成 | 记录来源、审核人与更新时间 | 

同名、重复工号、多份冲突或未知归属文件使用“处理状态：人工审核”，不强行归入无档案。混合问题保留全部原因，识别失败优先于信息缺失。

## Power Automate 配置步骤

### 01 · 主名单与队列

- 在受控 SharePoint 文档库保存花名册和档案，启用版本历史。将花名册设为 Excel 表 tblEmployees。
- 保留九项补录字段和工号、姓名。增加 EmployeeKey（文本工号）、RowOrder（原始序号）、BatchId，以及档案状态、处理状态、缺失字段、异常备注、文件名称、更新时间。
- 使用 Excel Online (Business) 的 List rows present in a table，开启分页，阈值覆盖全量员工；用批次快照固定顺序和人员范围。
- 按 RowOrder 升序创建 SharePoint WorkQueue。TaskKey = BatchId + EmployeeKey，启用唯一值；空工号、重复工号先转异常。
- 队列建立后才整理文件查找索引。目录枚举、分页与 OCR 归属索引均只用于检索，不产生新员工任务。

### 02 · 匹配与字段提取

- 定时流按序提取 Pending / Retry 任务。首版采用单任务处理；领取任务时记录 LeaseUntil、Attempt 和运行编号。
- SharePoint Get files (properties only) 取得候选元数据；按完整工号标记匹配，避免把 123456 匹配到 91234567。姓名精确匹配仅用于缩小候选集。
- 对未匹配文件建立内容索引：Get file content → 企业批准的 AI Builder 文本识别；同一 UniqueId + 文件版本只识别一次。姓名不能单独证明身份。
- 核对工号、姓名与档案归属。缺少任一身份依据或多个文件冲突时，停止自动补录并转人工。
- 读取九个字段，候选结果携带原文片段、页码、文件版本与提取规则版本；文字识别与结构化字段解析分成两步。
- 将候选写入 ReviewQueue。无依据返回空值；待审核展示可用“/”，不推测地址、电话、学历或日期。

### 03 · 人工审核与正式写回

- HR 在受限 ReviewQueue 查看原值、候选值和证据，逐字段选择确认、拒绝或修正，并记录审核人和时间。
- 只允许审核角色产生批准记录；提取流程不具有批准权限。可用 Approvals 发送任务链接，不在通知中放员工敏感字段。
- 独立写回流按序获取批准记录，重新核对工号、姓名、文件版本和原值。已有非空值保持不变；新旧冲突退回审核。
- 通过 Excel Online (Business) 按唯一 EmployeeKey 更新明确批准的空白单元格。更新前备份版本，写入后回读核对。
- 用 WriteKey = TaskKey + 审核版本记录提交凭据。若超时，先回读判断是否已经写入，再决定重试，避免重复操作。
- 写回窗口内关闭其他自动写入并协调人工编辑；Excel 不提供本流程所需的跨客户端原子比较写入，有并发编辑风险时暂停。

### 04 · 异常汇总与断点续跑

- Scope 分为 Try、Catch、Finally，通过 Configure run after 区分失败、超时与成功。
- 429 与临时 5xx 使用有上限的指数退避，遵循服务端重试提示；权限错误和文件损坏直接转异常，不循环重试。
- 任务保存检查点：候选定位、身份确认、提取完成、审核完成、写入完成。租约过期后可恢复，但先核对写入凭据。
- 已完成且文件版本、规则版本均未变化的任务跳过；补传档案或字段来源变化时创建新处理版本，不删除旧日志。
- 按 BatchId 筛选任务，按 RowOrder 排序生成汇总工作簿、无档案名单和异常名单。与原快照核对总行数及工号顺序。

## 表结构与连接器

### Excel 主表
工号、姓名、通讯地址、户籍地址、紧急联系人姓名 / 电话 / 关系、最高学历、学位、教育开始 / 结束时间。

工号与电话使用文本，保留前导零；教育时间保留来源精度，不把年月扩写为虚构日期。

结果列：档案状态、处理状态、缺失字段、异常备注、文件名称、更新时间。控制列：EmployeeKey、RowOrder、BatchId。

### SharePoint 数据层
WorkQueue：TaskKey、BatchId、RowOrder、EmployeeKey、Name、Stage、Attempt、LeaseUntil。

ReviewQueue：员工、文件版本、字段、原值、候选值、证据位置、缺失字段、异常原因、处理建议、审核状态与审核人。

FileIndex / AuditLog：文件标识与归属线索；阶段事件、错误码、写入凭据及受控版本链接。

索引 BatchId、Stage、EmployeeKey；避免全列表扫描和一次读取大对象。

组件 | 职责 | 

Excel Online (Business) | 读取主表、按唯一键更新、生成结果表 | 

SharePoint | 档案、任务、审核、版本与日志；Get files / Get file content / Get items / Create item / Update item | 

AI Builder | Recognize text in an image or a PDF document；识别之后再解析字段 | 

Approvals / Teams | 审核分发与异常提醒，通知仅含任务链接 | 

OneDrive for Business | 已获企业批准时可承接文件来源；团队长期档案优先 SharePoint | 

Microsoft Copilot | 辅助编写表达式和解释流程；不作为无人值守写入授权机制 | 

## 面向外企的 部署边界

### 替换数据通道，而非只替换模型
企业版通过租户批准的连接器和识别服务处理档案，不直接沿用初版的外部 DeepSeek / GPT API 调用路径。连接器策略、服务区域、数据保留、许可与 AI 容量由企业管理员核定。

### 最小权限与可追踪审核
档案读取、字段审核与写回权限分离。对包含原文的动作启用安全输入 / 输出，审计日志保存任务和版本引用；通知与公开作品集不携带真实档案。

### 顺序、吞吐与恢复
Excel 写回保持串行，识别缓存降低重复调用。正式批量前用小样本测量每页识别耗时、每员工动作数、节流和人工审核时间，据此决定批次规模。

### 回滚按单元格进行
保存批准前后的值与版本。回滚时仅恢复本批次写过、且当前仍等于写入值的单元格；后续人工修改不被整表备份覆盖。

## 验收用例
验收对象是正确归属、保留原值、审核门禁和可恢复性。

输入情况 | 预期结果 | 

打乱所有文件顺序 | 员工处理与输出顺序仍与 Excel 原始序号一致 | 

无档案、缺字段、模糊扫描、完整资料 | 四类状态分开；不以“/”代替档案状态 | 

同名、重号、姓名与工号冲突 | 进入审核，不自动写回 | 

部分文件未能读取或尚未完成索引 | 不提前把相关员工判成无档案 | 

Excel 原字段非空 / 审核后被人工修改 | 原值保留 / 冲突退回审核 | 

未批准、重复批准或伪造审核状态 | 写回门禁拒绝；重复请求不重复写入 | 

识别中断、写入响应超时、429 | 检查点恢复；写后回读；有限重试 | 

文件版本在审核后变化 | 原批准失效，重新核验来源 | 

约 6000 行主名单 | 分页覆盖全量；一人一任务；输出行数与原序一致 |
