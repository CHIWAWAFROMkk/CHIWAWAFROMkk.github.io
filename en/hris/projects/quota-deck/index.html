QuotaDeck: Quotas in One Place

Keep your attention on the task and your quota at hand.

In one minute

Problem & context
Quotas are scattered across agents and APIs, and one account balance shows up under a dozen models; step away for a while and you cannot tell which agent is done and which is waiting for approval.
Trade-offs
A quota that cannot be read shows as "unknown", not as used up; estimates, stale snapshots and disconnects are labelled with their source, and a failed refresh keeps the last good data and its time instead of pretending to be fresh.
What I did
Chose the direction and the scope: the interface copies Agent HUD, and reminders only read session logs without changing any agent's settings; set the quota display rules (pools apart from models, unreadable is not used up) and the reminder rules (done, waiting, approval); signed off the interface and the connections.
Tools & AI
The code was written with AI coding tools: GPT wrote the back end, Claude wrote the front end and reviewed and merged; the approval cards were implemented by DeepSeek from Claude's plan and reviewed by Claude. Electron and Node.js, with data reads in the main process and the interface getting data only through a restricted bridge.
What you can check
The desktop screenshots on this page (synthetic data) and the live edition, the public source and its automated checks; approval cards were signed off in a real Claude Code session.
Status
Personal project, MIT licensed; 0.7.0 is out and work continues. The screenshots and the live edition use synthetic data.

From a quota table to reminders on the desktop

When one account balance appears under a dozen models, it looks as if each model had its own allowance. The project first kept pools, models and billing apart, showing only what each provider actually reports. Later the interface moved to an edge HUD with done reminders and approval cards, and 0.7.0 added the notch. Step away for a while, glance at the strip when you are back, and you know which agent is done and which one is waiting for you.

The interface is a faithful copy of the minimal form of Agent HUD (jazzenchen/agent-hud-open, Apache-2.0); its look is not my design. My part was choosing the direction and the scope, setting the rules for reading quotas, for reminders and for approvals, and signing off the result.

Edge strip

One quota ring per service; the number is the share used (the balance for prepaid ones), green below 70%, amber from 70%, red from 90%, and – when nothing could be read. Hover an icon for a line of detail; click it for that service’s card: 5-hour and weekly windows, reset times, and for Claude and Codex 24 hours of token bars stacked by model.

Done reminders

QuotaDeck only reads local session logs and changes no Claude Code or Codex setting. Seconds after a turn ends the icon becomes a smiling bot and a New reply capsule slides out; the reminder stays until you have seen it. Waiting is an inference: a tool call with no result after 30 seconds is taken as possibly waiting for you, so a long command (a build, say) gets marked this way too.

Approval cards

Once connected, a command Claude Code asks to run appears as a card on the HUD, with Allow once and Deny. It is off by default; connecting backs up the existing settings first, and one click disconnects. When QuotaDeck is not running, requests fall back to the usual confirmation.

Notch

The strip can also become a black block at the top centre of the screen (the notch): its glow takes each service’s quota colour, it opens out to both sides when there is a reminder, and cards hang below it. Game mode hides the whole HUD at once: press Ctrl+Alt+H or tick it in the tray menu, and again to bring it back. QuotaDeck does not guess what you are doing; reminders and approval requests that come in meanwhile are held and appear when the HUD comes back.

Connections and current scope

Service Data source Current limits
Codex Local CLI: account windows and model list A shared quota is never split into made-up per-model shares
Claude Code Reads the local sign-in to call the official usage endpoint; falls back to data forwarded by the official statusLine The sign-in token stays in the main process, never in snapshots, logs or the interface
Antigravity The local service’s quota and model catalogue, falling back to the CLI Experimental interface that may change with client versions
DeepSeek Official API for balance and models Needs the user’s own API key; the account balance is shared
WorkBuddy An official web snapshot the user saved Does not refresh the web page; balance and multipliers are as of the snapshot time

Build and verification

Electron and Node.js. Data reads stay in the main process; the interface only gets data through a restricted bridge. The code was written with AI coding tools: GPT wrote the back end, Claude wrote the front end and reviewed and merged; the approval cards were implemented by DeepSeek from Claude’s plan and reviewed by Claude.

Unit tests and desktop smoke tests cover quota mapping, session states, reminders and approvals; approval cards were signed off in a real Claude Code session: allowed commands ran, denied ones did not. Tests and builds never call a real account.

The live edition of this page runs the same HUD interface files in your browser, on simulated data.

Run it on your own computer

Prepare Windows 11, Node.js 22+ and PowerShell 7, then install and sign in to the CLIs you need, following the repository README.

git clone https://github.com/CHIWAWAFROMkk/quota-deck.git
cd quota-deck
npm ci
npm run check
npm start

The repository’s packaging script also builds a portable version (unsigned; it does not bypass Windows security prompts; a per-file SHA-256 manifest is included).

Neither the public source nor the build contains private usage snapshots, sign-in credentials or API keys. This project page only describes the tool; it does not connect to the visitor’s computer or read any account.
