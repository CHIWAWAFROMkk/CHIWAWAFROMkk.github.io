QUOTADECK.

AI 额度显示器 · Windows 桌面应用

MIT 开源 · 0.3.1查看源码与运行方法当前完成范围

把分散在不同 Agent 和 API 里的额度放到一个桌面入口：先看还能用多少，再展开模型消费倍率，最后按任务给本地 Agent 分工。

从模型列表到使用判断

同一个账户余额重复出现在十几个模型下，会让人误以为每个模型都有独立额度。项目把额度池、模型与计费关系分开，保留服务商真实提供的信息。

额度

按服务商折叠，共享池只展示一次。Antigravity 显示额度窗口、重置时间和采样消耗速度；WorkBuddy 展示模型消费倍率。

模型库

收集已连接服务当前返回的模型，支持搜索。模型擅长领域标为本地建议，避免把启发式标签当成官方评测。

并行分工

同一任务分别交给 Codex 做技术方案、Antigravity 做替代方案、WorkBuddy 做交付结构，等待独立结果并列展示。

连接方式与当前范围

服务数据来源当前边界
Codex本机 CLI：账户窗口、模型列表共享额度不虚构模型独立份额
Antigravity本机语言服务器与 CLI实验性接口，随客户端版本可能变化；速度按额度池采样
DeepSeek API官方余额与模型接口需要用户自己的 API 密钥；账户余额共享
WorkBuddy用户保存的官方网页快照目前不自动刷新网页；余额和倍率以快照时间为准

目录覆盖连接器返回的模型，不承诺发现任意本地 Agent。第三方名称与商标归各自权利人所有。

倍率怎样解释

以相同计费基准为前提，消费倍率越低，同一余额支持的用量越多。界面用倍率的倒数帮助比较。

计算示例，不是账号实测

假设两个模型消费倍率分别为 0.5× 和 1×，相同输入输出条件下，前者的相对可用量是后者的 2 倍。

这不能换算成精确请求次数；上下文长度、输出长度、缓存与折扣都会改变实际消耗。服务商未公开模型倍率时保留未知。

实现与验证

Electron 托盘窗口与 Node.js 连接器。读取数据和模型调用放在主进程，界面通过受限桥接请求操作。

已验证

8 项自动检查覆盖共享额度映射、结果解析与状态边界；开发机完成了 Codex、Antigravity、WorkBuddy 的短任务并行连通性验证。CI 检查与构建不调用真实账号模型。

仍待扩展

多轮互审、自动汇总、任意 Agent 自动发现以及模型级精确消耗归因尚未实现。能力建议目前来自名称规则，尚未通过实际基准校准。

在自己的电脑运行

准备 Windows 11、Node.js 22+ 和 PowerShell 7，按仓库 README 安装并登录所需 CLI。

git clone https://github.com/CHIWAWAFROMkk/quota-deck.git
cd quota-deck
npm ci
npm run check
npm start

公开源码和构建包均不包含私人用量快照、登录凭证或 API 密钥。此项目页只介绍功能，不连接访客电脑或读取账号。实际并行任务会消耗所选服务商的额度。
