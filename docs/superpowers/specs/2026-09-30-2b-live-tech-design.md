## 1. 共用的浏览器 Python 运行时

求职页和校园研究页共用。

- **版本**：Pyodide 0.29.5（Python 3.13.2）。随附包：pydantic 2.12.5、pydantic_core 2.41.5、typing_extensions 4.15.0、annotated_types 0.7.0、typing_inspection 0.4.2。满足求职引擎的 `requires-python >=3.12,<3.14` 和 `pydantic>=2.10,<3`。引擎导入链经 `job_repository` 用到 `sqlite3`；是否需要额外随附 Pyodide 的 sqlite3 包，以实际导入测试为准。
- **文件**：放在 `public/vendor/pyodide/0.29.5/`，只放用到的文件。下载脚本 `npm run py:vendor` 从 Pyodide 官方发布地址取文件，写一份清单（文件名、来源地址、SHA-256、字节数）。单元测试核对清单里的每个文件都存在且哈希一致。总体积预计 12–15 MB，实施时按实测写进页面文案。
- **运行位置**：一个 Web Worker，页面主线程不被阻塞。每个页面最多一个运行时实例。
- **消息协议**：
  - 页面 → Worker：`boot`；`call { id, module, fn, args }`（参数和返回值都是 JSON）。
  - Worker → 页面：`progress { step, label, bytes, ms }`、`ready { python, pyodide, ms }`、`result { id, value, ms }`、`error { id, message }`、`event { id, data }`（测试逐条推送等流式结果）。
- **冷启动如实显示**：进度里的字节数来自清单和资源计时（Resource Timing），耗时是实测值。冷启动动画（十六进制字节流、日志行、模块标签收拢）直接显示这些真实数字；芯片上的版本号取运行时实际报告的 Python 版本。
- **何时加载**：
  - 桌面：演示区进入视口时开始加载。
  - 手机（窄屏或粗指针）、开启省流量（`navigator.connection.saveData`）：显示"启动引擎（约 N MB）"按钮，N 取自清单总和，点了才加载。
- **超时与失败**：60 秒未就绪、WebAssembly 不可用、Worker 创建失败或内存不足，都退回该页原有的备用内容（见各页），并给出可读说明和重试按钮。

## 2. 求职 Agent · 证据电路

### 引擎

- 从公开仓库 `CHIWAWAFROMkk/personal-job-agent` 的 `4397ded9c603e7e26d3dc241eb910ce3ad0a749a` 原样复制：`src/job_agent` 下导入链用到的 16 个模块，以及虚构候选人样例 `tests/helpers.py`。放在 `public/assets/py/job-agent/4397ded/`，附清单（提交号、每个文件的 SHA-256）。复制脚本 `npm run job-agent:vendor` 需要本机公开仓库的检出路径，并先核对检出的提交号。单元测试核对清单。
- 胶水代码 `career_bridge.py`（本站自写，保持很短）：
  1. 以 `sample_profile()` 为底，按访客的改动建档：每周到岗天数、各条事实的确认状态、新增或删除的经历。
  2. 包装 `_cap_breakdown`，读出封顶前的原始总分和封顶线。
  3. 调用 `structure_job_locally`、`match_job_locally`、`build_application_pack`，把结果整理成 JSON 返回：要求列表、逐项证据、硬门槛、原始总分、封顶线、最终分数、推荐程度、入选材料的事实、人工确认清单、材料草稿、计算耗时。
- 输入限制：职位描述不超过 20,000 字；新增经历每条不超过 200 字、最多 20 条；超限时给出提示，不调用引擎。

### 界面

- 职位描述输入框，预填现在的虚构范例。
- 候选人编辑区：到岗天数，每条事实的确认状态开关，新增或删除经历。
- 改动后自动重新计算（停手 600 毫秒后），也可以点"重新计算"。
- **证据电路按引擎的真实输出排布**：
  - 左列是引擎解析出的要求（按引擎顺序）。
  - 右列是候选人事实。
  - 连线状态直接取自逐项证据和硬门槛：满足、证据缺口、待确认、不满足。
  - 要求条数不固定。超过 8 条时压缩行高；仍放不下时，电路区域内部可以滚动，页面本身不横向溢出。
- **动效**（第二版原型的水平）：
  - 冷启动。
  - 扫描线扫过职位描述，要求原文逐条飞进电路。计算时用一个只读的解析视图覆盖输入框：在原文里找到引擎给出的要求文字并高亮；找不到时从面板顶部飞出。
  - 满足的线路有带光晕的电子流过；待确认是虚线；证据缺口是暗红虚线并偶尔闪烁；不满足的线路放电弧、冒火花。
  - 确认一条经历时，那条事实先充能，再沿线路冲进"材料草稿"。
  - 分数用机械滚轮滚向原始总分，撞上封顶线时封顶线砸下，整块震动，并有克制的暗角闪光。原始总分不超过封顶线时不做撞击，正常滚到结果。
- **代码实况**：`local_matcher.py` 第 697–702 行。源码在构建时从复制来的文件读取，保证逐字一致。执行到的分支同步亮起：失败门槛为红色，待确认门槛为琥珀色。
- 结论一句：由结果生成，沿用现有文案口径。

### 备用

现有的六组引擎回放（`CareerDemo`）保留。运行时不可用或失败时显示它，并注明原因。

## 3. QuotaDeck · 时间机器

### 真实代码

- 从本机 QuotaDeck 仓库复制，提交号固定为 `e9557c62f00a085299e5d3d06e9259ed19688ef8`（与 GitHub 公开的 `main` 一致）。复制时先核对 HEAD。
  - 界面：`src/renderer/compact.html`、`compact.css`、`compact.js`，不做任何修改。
  - 主进程逻辑：`snapshot.cjs`（`providerToUi`、`toUiSnapshot`）、`quota-history.cjs`（消耗速度与耗尽预测），以及它们在浏览器里需要的规范化函数。
- 复制脚本 `npm run quotadeck:vendor` 生成清单（每个文件的 SHA-256）。单元测试核对清单。
- **浏览器替身**：
  - `node:fs/promises` 换成内存文件系统（Map 实现）。
  - `node:path` 换成最小实现。
  - `node:crypto` 的 `randomUUID` 用浏览器自带实现。`createHash` 只在传入账号范围时才会调用，演示从不传入；替身在被调用时直接报错，防止静默出错。
  - `snapshot.cjs` 顶部引入的各家连接器（codex、deepseek、workbuddy、antigravity、claude、orchestrator）换成空实现，保证网页里没有任何读取真实账号的代码路径。
  - 以上都通过构建工具的路径别名完成。
- **界面宿主**：一个同源的内嵌页面先把 `window.quotaDeck` 指向页面提供的桥接对象，再加载原样的 `compact.js`。窗口按 520×840 渲染，窄屏按比例缩放。

### 模拟器

- 只负责四件事：
  1. 时钟：1×、60×、600×，默认 600×。
  2. 使用量模型：各服务的消耗带平滑噪声，5 小时窗口，到点重置。
  3. "派一个大任务"：额度骤降。
  4. 并行协作的状态流程：排队中 → 运行中 → 已完成。
- 其余全部走真实代码：
  - 每个采样点交给真实的 `createHistory(...).record()`，由它算出 `burnPerHour` 和 `estimatedHoursLeft`。
  - 界面数据由真实的 `providerToUi` 和 `toUiSnapshot` 生成，经桥接推给界面。
- 并行协作按真实 orchestrator 的状态结构返回（实施时读 `orchestrator.cjs` 确认字段）。结果区写明"网页演示：状态流程与额度变化为模拟，不调用真实 Agent，不生成回答"，不出现任何编造的回答。
- **动效**（第二版原型的水平）：
  - 机械滚轮时钟；昼夜分带的时间轴；带光效的曲线。
  - 重置时扫描线划过，并在时间轴上留下标记。
  - 采样刻度，加上延伸到 0% 的预测虚线和"耗尽 T-x.xh"倒计时（不足 1 小时时脉动）。
  - 大任务时有冲击波和火花。
  - 并行协作时 4 个 Agent 节点由连线接入。
- **代码实况**：`quota-history.cjs` 第 50–61 行。构建时从复制来的文件读取，并在旁边显示实时计算值。

## 4. AI 校园研究 · 清洗流水线

### 真实程序

- 使用网站已提供下载的 `public/downloads/campus/analysis.py` 和 `test_analysis.py`，同一份文件，不另做副本。单元测试核对 Worker 加载的就是这两个地址。

- 校验失败（`analyze()` 抛出的 `ValueError`）照原样显示在红色"校验失败"面板里，这也是程序的真实行为。

### 数据

- 访客按真实问卷填写（Q1–Q7 对应程序的数据字段），填一份算一份。
- 36 份构造样本（故意混入重复 ID、未同意、不符合人群、超出采集窗口）。
- 2,000 份压力测试数据，在 Python 里用固定随机种子生成，组成比例可复现。
- 所有构造数据都标明"构造样本 · 不是 2024 年调查结果"。

### 界面与动效

- 粒子流水线**按真实的分支序列回放**：每个粒子对应一份回答，在它真实走进的那道关卡被排除或通过。
- 四道激光关卡；被排除的溅出火花并掉进下方柱子；通过的填进"纳入"点阵。
- 统计栏直接取 `analyze()` 的输出：纳入 / 输入、主动使用比例、共用分母的场景比例、有帮助程度分布与中位数。

- 耗时标签显示真实毫秒数。

## 5. 通用规范

- **动效**：以第二版原型为准。
  - 亮度克制：闪光不超过 0.35 不透明度，没有整屏白闪。
  - 震动不超过 8 像素、400 毫秒。
  - 关键时刻至少 50 fps。
- **减少动态效果**：直接显示最终状态（最终分数、最终计数、测试结果），不播放冷启动、飞入、粒子和震动。数据照常计算。
- **手机**（390 宽）：
  - 电路改为纵向排列（要求在上、事实在下，连线变短）。
  - QuotaDeck 窗口和时间轴上下排列并缩放。
  - 流水线降低粒子数和拖尾，但数据不变。
  - 页面都不能横向溢出。
- **英文页**：
  - 界面、标签、说明用英文。
  - 引擎数据（职位描述、候选人事实、材料草稿、QuotaDeck 界面）保持原样的中文，注明 "The engine is designed for Chinese job descriptions" 或相应说明。
  - 代码实况原样显示源码。
- **诚实与数字**：
  - 所有实时数字都由真实程序算出，演示区放在 `[data-demo]` 内（数字测试排除它）。
  - 访客输入只在自己的浏览器里计算，不上传，页面上写明。
  - 并行协作不调用真实 Agent。
  - 所有演示数据和构造样本都有标注。
  - "借助 AI 编程工具开发"的口径不变。
- **颜色**：只用 tokens 变量，画布颜色也从变量读取。
