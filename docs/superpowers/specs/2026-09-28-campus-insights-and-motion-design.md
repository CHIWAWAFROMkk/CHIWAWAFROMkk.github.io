## 1. 目标

两件事，一次完成：

1. **新增项目**「校园外卖经营分析（进阶版）」：在课程设计数据库的基础上，用一个学期规模的合成数据回答五个经营问题。前半页是滚动叙事，后半页是可自由筛选的驾驶舱。

- HR 快速划过进阶版页面，不点任何东西，就能读到五条经营结论和三条建议。
- 懂数据的面试官能看到每个数字背后的 SQL，并能在驾驶舱里自己筛选验证。
- 网络拉不到 SQL 引擎时，滚动叙事照常完整显示；只有驾驶舱给出可读的失败提示。
- 旧页面加动效后，原有功能和测试全部照旧通过。

- **合成数据的规律是预设的。** 页面在开场摘要和"方法与下载"两处写明：高峰时段、远宿舍区配送慢、退款原因比例等规律由生成脚本设定；本项目展示的是提出问题、定口径、写 SQL、读结果的方法，不是真实经营发现。
- **分工。** 摘要五行里：
  - 我的工作：在课程设计数据库的基础上，提出五个经营问题、确定指标口径、审核每条结论；数据生成、图表和页面借助 AI 编程工具完成。
  - 状态：进阶版 · 借助 AI 编程工具开发 · 合成数据。
- **数字来源。** 进阶版页面上关于数据的每个数字都来自查询结果文件（第 7.2 节），由测试逐个核对；关于作者本人的数字仍只来自 `src/data/facts.ts`。结论文案由模板函数拼入数字，不手写数字。
- **建议章节**标明是"建议"，不写成数据结论。

## 5. 五个经营问题与口径（用户已确认）

合成数据覆盖一个学期：16 周，约 600 名学生、12 家商家、约 8000 笔订单（订单数以数据库文件体积上限为准，见 7.1）。

| 章 | 问题 | 图 | 口径 |
|---|---|---|---|
| 1 | 什么时候最忙？ | 星期 × 小时订单热力图 | 订单数，按下单时间 `created_at`，含已退款订单 |
| 2 | 钱从哪里来？ | 商家净收款排名 + 累计占比曲线（帕累托） | 净收款 = 支付 − 退款；按订单粒度连接支付与退款，避免一对多重复 |
| 3 | 学生会回来吗？ | 首单周群组 × 之后各周的留存矩阵 | 首次下单所在周为一组；之后某周有至少 1 笔未退款订单即算该周留存 |
| 4 | 送得够快吗？ | 配送时长分布，按宿舍区拆开 | 时长 = `delivered_at` − `created_at`，只计已送达订单；另报超过 45 分钟的占比 |
| 5 | 为什么退款？ | 退款原因构成 + 各时段取消率 | 退款率 = 退款订单 ÷ 全部订单；只有未送达订单能退款（课程设计规则） |
| 6 | 如果我是运营 | 三条建议卡片 | 每条建议引用前五章的一个数字；标为"建议" |

## 6. 进阶版页面

### 6.1 位置与导航

- 网址：`/projects/campus-delivery/insights/`，英文 `/en/projects/campus-delivery/insights/`。
- `SITE.projects` 在 `campus-delivery` 之后插入 `campus-insights`：`line: 'data'`，`inBrief: false`，`href` 为上述网址。标题：「校园外卖经营分析（进阶版）」/ "Campus Delivery Insights (advanced)"。
- 项目总目录因此多一行；项目页底部的上一篇 / 下一篇随之调整。
- SQL 页正文末尾（"项目交付"之后）加一条醒目入口：「进阶版：一个学期的经营分析 →」。

### 6.2 页面自上而下

1. **开场**：几千个代表订单的小点像下雨一样落下，约 1.2 秒后汇聚成巨字"N 笔订单"（N 取自查询结果）。只播一次；点击、滚动、按键立即跳到终态。随后是与其他项目页一致的标签、标题、导语和五行摘要。
2. **滚动叙事**（第 5 节六章）：
   - 电脑上左侧文字、右侧图表舞台 `position: sticky`。
   - 同一池图形（约 168 个矩形，对应 7 × 24 热力格）随滚动进度在各章布局之间插值变形：热力格 → 商家柱 → 留存矩阵 → 时长直方图 → 退款构成。多余的图形收缩到相邻图形里并淡出。
   - 变形完全由滚动进度决定，往回滚即倒放；不自动播放。
   - 每章关键数字进入视野时滚动计数一次。
   - 每章图表都有等价的文字替代：可展开的数据表。
3. **驾驶舱**（暗场背景）：
   - 筛选：周范围（1–16，双端滑块）、商家（多选）、宿舍区（多选）。
   - 指标条：订单数、净收款、客单价、退款率、平均配送时长。
   - 四张联动图：热力图、商家排名、配送时长分布、退款原因。点击柱子或色块即按它筛选，再点取消。
   - 每张图可展开"查看 SQL"：显示实际执行的 SQL（逐行显现）和原始结果表。
   - 筛选变化时，图形平滑过渡到新值，指标数字滚动变化。
4. **方法与下载**：数据生成规则（写明哪些规律是预设的）、全部 SQL、数据库文件下载、生成脚本下载。

### 6.3 克制规则

- `prefers-reduced-motion: reduce` 时：开场直接显示终态；叙事每章显示该章静态图；驾驶舱无过渡。
- 手机（宽度 ≤ 800px）：图表舞台固定在屏幕上半部分，文字在下半部分滚过；驾驶舱改为单列。
- 除滚动联动外，单次动效不超过约 0.6 秒；开场不超过 1.2 秒。

### 6.4 双语

- 界面、章节文案、图例、指标名为双语。
- 商家名、宿舍区名在图表中通过对照表显示英文；"查看 SQL"里的原始结果表保持数据库原值（中文），与 2A 的做法一致。

## 7. 技术结构

### 7.1 数据生成（构建前，一次性）

- `tools/gen-insights.mjs`：在 Node 里用 `public/assets/vendor/sql-wasm.js`（沿用 2A 测试里 `new Function` 的 CommonJS 加载方式），先执行 `delivery-schema.sql` 的建表、约束与触发器部分（不含其中的演示数据），再用固定种子的伪随机数逐笔写入订单、明细、支付、配送、退款。所有写入经过原有触发器，因此数据满足课程设计的全部规则。
- 预设规律：午餐与晚餐双高峰、周末夜宵；少数商家贡献大部分净收款；新生前几周留存更高；远宿舍区配送更慢；高峰时段取消率更高。规律参数集中写在脚本顶部，下载页原样列出。
- 输出：
  - `public/assets/insights/campus-term.sqlite`：执行 `VACUUM` 后体积不超过 1.5 MB；超过则减少订单数，直到满足。
  - `src/data/insights.json`：第 5 节每章查询的结果，加上开场数字。
- 两个文件都提交进仓库；构建网站时不运行生成脚本。
- 生成是确定性的：同一种子、同一脚本，输出逐字节相同。

### 7.2 查询定义（单一来源）

- `src/scripts/insights-queries.ts`：每个查询有 `id`、SQL、所需参数（周范围、商家、宿舍区），只读。生成脚本、单元测试、浏览器驾驶舱都从这里取 SQL。
- 叙事用的是"无筛选"参数下的结果；驾驶舱用绑定参数，不拼接字符串。

### 7.3 浏览器端

- `public/assets/insights-worker.js`：加载 sql.js 与 `campus-term.sqlite`，只接受"按 id 运行查询 + 参数"，有超时，与 2A 的工作线程同样处理错误（`unhandledrejection` 与 `onerror` 不外溢）。
- 引擎与数据库在驾驶舱进入视野约四分之一，或访客聚焦驾驶舱内的控件时才下载（与 2A 相同的规则）。失败时显示可读提示，控件保持禁用；叙事部分不受影响。
- 图形：
  - `src/scripts/morph.ts`：纯函数。`layouts(data, size)` 返回每章的矩形数组；`interpolate(a, b, t)` 返回中间态；`chapterProgress(scrollY, anchors)` 把滚动位置映射为（章，t）。
  - `morph-dom.ts`：只负责把矩形写进 SVG，以及滚动监听（`requestAnimationFrame` 节流）。
  - 开场的点雨用 `<canvas>`（`src/scripts/rain.ts` 纯函数 + `rain-dom.ts`）。
  - 驾驶舱图表用 SVG，过渡用同一个 `interpolate`。

### 7.4 数字核对

- 进阶版页面中，数据数字放在 `[data-insight-num]` 元素里，渲染自 `insights.json`。
- 新测试：页面里每个 `[data-insight-num]` 的文本等于 `insights.json` 中对应值的格式化结果；页面其余文本中出现的数字仍走现有的事实清单检查（`[data-insight]` 区域整体排除在事实清单检查之外，改由上一条核对）。

## 8. 旧页面动效

### 8.1 校园外卖 SQL 页

- **关系图**：正文里的 `delivery-relations.svg` 图片改为组件内嵌的等价 SVG，放在正文"关系模型"标题下（Markdown 里的图片行移到组件，文字说明不变）。进入视野后 8 张表依次出现，外键连线按滚动进度画出。图片仍保留 `alt` 等价的文字说明。
- **事务进度带**：下单表单旁显示五步，即扣库存 → 写明细 → 登记支付 → 生成配送 → 提交。
  - 顺序与 `delivery-core.mjs` 中 `place()` 实际执行的语句顺序一致（以源码为准，计划阶段逐条核对）。
  - 成功：五步依次点亮后显示"已提交"。
  - 失败：按触发器报错定位失败步骤（库存不足 → 扣库存，价格快照不一致 → 写明细，支付金额与明细不一致 → 登记支付；份数或菜品校验在事务之前，显示为第 0 步未通过），已点亮的步骤倒退熄灭，显示"已回滚"。
  - 退款有一条三步进度带：校验状态 → 写退款 → 恢复库存并改状态。
- **查询结果**：前 20 行依次落下（每行约 20ms 间隔），其余直接显示；行数计数滚动增加。
- **关键决策**六条：滚动时依次升起，序号有一次红色划过。

### 8.2 CSV 工具页

- 勾选"移除完全重复行"或"移除含空白值的行"时，预览表里将被移除的行先划线、再收起（被移除的缺失行先变灰下沉）；行数审计的数字滚动变化。终态与现在完全一致。
- 直方图柱子从零长到实际高度。
- 出错时输入区轻微抖动一次并出现红色边线；原有结果保持不动。

### 8.3 过程与运行子页

- 处理步骤显示为竖向时间线，线条随滚动向下画出，经过的步骤点亮；关键数字进入视野时滚动计数。

### 8.4 项目总目录

- 各行滚动进入时依次滑入。
- 鼠标悬停（或键盘聚焦）某行：红色色带从左向右扫过，序号翻动一次，右侧浮出项目预览图并跟随鼠标。
  - 预览图：档案补录、SQL 工作台、CSV 工具用现有编辑插图；进阶版用构建时由 `insights.json` 生成的热力图 SVG。没有预览图的项目（2B 待做）不浮出。
  - 触屏设备不浮出预览。
- 背景有一个超大的"PROJECTS"字样，随滚动缓慢横移（纯装饰，`aria-hidden`）。

### 8.5 统一原则

- 所有动效在减少动态效果模式下关闭，页面直接显示终态。
- 不自动循环。
- 动效不改变 DOM 的最终内容和阅读顺序；现有 e2e 测试不需要为动效改断言。

## 9. 测试

**单元**
- 生成脚本确定性：同一种子运行两次，数据库与 JSON 逐字节相同；并与仓库中提交的文件相同。
- 数据满足规则：订单总额 = 明细合计 = 支付额；退款只出现在未送达订单；数据库文件 ≤ 1.5 MB。
- `insights-queries.ts` 在无筛选参数下的结果等于 `insights.json`。
- `morph.ts`：`interpolate` 在 t = 0 和 t = 1 时等于两端布局；`chapterProgress` 单调，边界正确。
- 事务步骤映射：每条触发器报错映射到正确的步骤。

**端到端**
- 进阶版中英页：屏蔽 `.wasm` 时，叙事六章和全部数字照常显示，驾驶舱显示可读的失败提示，没有页面错误。
- 驾驶舱：改变周范围后，指标条的订单数等于在同一参数下直接执行 SQL 的结果；点击商家柱子后，其他图随之更新；"查看 SQL"显示的 SQL 与 `insights-queries.ts` 一致。
- 数字核对（第 7.4 节）。
- 减少动态效果：开场直接显示终态，叙事各章为静态图。
- 手机：无横向溢出，舞台固定在上半屏。
- 无障碍：axe 无违规；图表都有可展开的数据表。
- SQL 页：成功下单时进度带五步全部点亮；库存不足时停在"扣库存"并显示"已回滚"。
- CSV 页：勾选去重后，终态行数与现在一致。
- 总目录：悬停一行出现预览图；键盘聚焦同样出现；触屏不出现。
- 现有全部测试照旧通过。
