# 作品集双轨重构：AI 产品主站 + HRIS 保底站（设计）

日期：2026-10-14 · 状态：待用户审阅

## 1. 目标

把作品集从"数据分析 · AI 应用 · AI 影像"的综合站，改成两条互不串线的展示线：

- **AI 主站**（`/`）：面向 AI 产品经理实习与 AI 产品运营岗位。
- **HRIS 站**（`/hris/`）：面向 HRIS、People Analytics、HR 数字化岗位，作为保底。主站不挂任何入口，只通过 HR 版简历上的链接进入。

两条线共用同一个仓库、同一份事实台账和同一批重型演示（Pyodide、sql.js 等大文件只有一份）。

成功标准：
- 招聘方从任意一条线进入，从头到尾只看到这条线的定位、导航和项目排序；转发任何一个页面链接也不会串到另一条线。
- 两条线上出现的每个数字都来自 `src/data/facts.ts`，现有的数字检查测试覆盖两条线的所有页面。
- 访客开着"减少动态效果"或用低性能设备时，仍能看到动效（温和档或轻量档），只有在访客自己选择"关"时才完全静止。
- 现有单元测试和端到端测试全部通过；新增页面与新增行为有对应测试。

背景材料：用户 2026-10-14 提供的 Gemini 对话归档（`CLAUDE_MASTER_STRATEGY_AND_FULL_DIALOG.md`）、HRIS V3 页面（`hris_portfolio_v3_architectural.html`）与一键拆分脚本。这些材料只作为方向参考：其中与经历档案冲突的写法不采纳（见第 9 节），脚本针对的是构建产物，不运行。

## 3. 架构

### 3.1 路由

中文为默认语言、不加前缀，英文加 `/en/` 前缀，与现有做法一致。所有 `/hris/` 页面带 `<meta name="robots" content="noindex">`，不写进 `sitemap.xml`，主站上没有任何链接指向它们。

| | AI 主站 | HRIS 站 |
|---|---|---|
| 首页 | `/` | `/hris/` |
| 一分钟版 | `/brief/` | `/hris/brief/` |
| 全部项目 | `/projects/` | `/hris/projects/` |
| 项目详情 | `/projects/<slug>/` | `/hris/projects/<slug>/` |
| 完整版 | `/projects/<slug>/live/` 等 | `/hris/projects/<slug>/live/` 等 |
| 流程终端 | — | `/hris/workbench/` |

HRIS 站只生成它收录的 5 个项目的详情页与完整版页。影像、CSV 工具没有 `/hris/` 版本。

### 3.2 `track` 参数

仓库现有的做法是：每个页面文件只有一行，调用 `src/views/*View.astro` 并传入 `lang`。这次在同一处再传入 `track: 'ai' | 'hris'`：

- `src/pages/hris/**` 下的页面文件调用同一批 View，传 `track="hris"`。
- `View`、`ProjectLayout`、`Nav`、`Footer`、`ContactBar`、`LiveView` 读取 `track`，决定导航目标、返回链接、品牌链接、副标题、简历按钮指向，以及使用哪一套外壳。
- 链接一律通过新增的 `trackPath(track, lang, path)` 生成（扩展现有 `src/i18n.ts` 的路径工具），不在组件里手写 `/projects/...`。单元测试检查：`track='hris'` 下渲染出的站内链接全部以 `/hris/` 或 `/en/hris/` 开头（下载文件、公共静态资源除外）。

### 3.3 数据

- **新建 `src/data/tracks.ts`**：两条线各一份配置，包括定位语、标语、开场词、项目顺序、每个项目在这条线上的卡片标题与简介、技能标签、数字条、简历链接、强调色主题名。凡是两条线说法不同的文字都放在这里。
- **`src/data/site.ts`**：保留两条线共用的内容（姓名、导航标签、摘要栏标签、各项目详情页正文用到的文案等）。`SITE.projects` 改为"一个项目一条"，简易版与完整版不再各占一条，每条带 `live?: { href, sizeKey }`。
- **`src/data/facts.ts`**：仍是唯一的数字来源。按第 4.1 节更新 F1、F5，并补入 `hris-delivered` 分支的 F14。
- **邮箱**：`SITE.email` 继续作为唯一配置点；`src/copy/privacy.{zh,en}.md` 里写死的邮箱改为构建时插入。

### 3.4 HRIS 外壳与换肤

- 新增 `src/layouts/HrisBase.astro`（顶栏、深浅色切换、页脚）与 `src/layouts/HrisProjectLayout.astro`（标题区、摘要网格、正文排版、翻页），按 Gemini V3 的结构与比例移植：`#F4F3EF` 纸色、1px 结构线、60px 标题对 11px 等宽索引的字号反差、`01 // 04` 式编号。
- 新增 `src/styles/hris.css`，只在 HRIS 外壳下生效。V3 的颜色进入 `src/data/tokens.ts`，新增一组 `HRIS_COLORS`（浅色、深色各一套），同样由 `contrast.test.ts` 检查对比度。
- **演示组件不改结构，只换变量**：组件里引用颜色变量的地方有 447 处，写死的颜色只有 47 处，且集中在影像相关组件，HRIS 站不用这些组件。所以在 HRIS 外壳下覆盖 `--red`、`--red-text`、`--red-fill`、`--paper`、`--ink` 等变量，即可把演示组件换成钴蓝和纸色。读取 `COLORS` 的 Canvas 脚本改为读取当前的 CSS 变量。
- 深色模式下，演示组件放在浅色纸底的嵌入面板里，不为每个演示单独做深色适配。
- 选择记在 `localStorage`（读写包在 try/catch 里）；默认跟随系统。

### 3.5 发布

沿用现有方式：源码提交到 `redesign`，构建产物推到 `main`。每一期上线前先给用户看，用户同意后才推送（与 HRIS 页"看过再上线"的规则一致）。

## 7. 动效

### 7.1 AI 主站：执行轨迹

1. **开场**：三个词以流式输出的方式逐块出现，带等宽字体光标；最后一个词结束后，一条朱红细线从词尾画出，连到首屏姓名，随后幕布收起。全程约 2.5 秒，Esc 和按钮都能跳过；只在首次访问时播放（沿用现有规则）。
2. **首屏背景**：姓名后面的发丝网格上有 6 个节点，组成一次 Agent 运行：输入 → 规则 → 证据 → 判断 → 输出。每 4–6 秒，一个红色脉冲沿连线走一遍，节点依次打上等宽字体的 `✓`。鼠标靠近时，最近的节点被吸近，位移不超过 6px（沿用磁吸上限）。用 SVG 加 GSAP 实现。
3. **正文出现**：段落按块像流式输出那样出现（每块 40–60ms，块大小按中文字数和英文词数切分），替代通用的上浮淡入。标题保留现有的逐字拆分动画。
4. **项目卡**：悬停或键盘聚焦时，一条红线沿卡片边框描一圈（`stroke-dashoffset`），两个按钮滑入；"在浏览器里运行"按钮上的细进度条按加载体积显示比例。
5. **阅读进度**：一分钟版和项目详情页左侧有一条竖向轨迹，每个章节一个节点，当前章节的节点亮起。窄屏时改为顶部细条。
6. **影像区**：进入暗场时先淡黑再亮起（不闪白），现有的影院式横向滚动保留。

### 7.2 HRIS 站：治理收敛（沿用 Gemini V3）

1. **开场幕布**：黑底上字母先散开，再由弹簧阻尼拉回基线对齐；同时 1px 网格线横贯全屏，然后幕布抬起。约 2.2 秒，Esc 可跳过，只在首次进入 `/hris/` 时播放。
2. **首屏拓扑**：Canvas 2D 绘制约 2000 个点。"治理前"是离散漂移，"治理后"是弹簧阻尼收进三组网格。可手动切换两种状态，鼠标靠近时点被推开。点的颜色治理前为钴蓝、治理后为森林绿，并随深浅色切换。图上标注"示意"。
3. **数字条**：等宽数字像机械计数器一样滚到位，1px 分隔线同步画出（复用现有的 odometer）。
4. **结构线**：滚动时章节之间的 1px 线从左向右画出，章节编号 `01 // 04` 随之跳动。
5. **流程终端**：选中样例档案后，字段一行行对齐进表格列，流程节点依次点亮，分流结果以盖章的方式落下；切换版本时流程图在三种形态之间变形过渡。
6. **深浅色切换**：颜色平滑过渡，Canvas 的点同步换色。

### 7.3 三档与开关

| 档位 | 触发 | 行为 |
|---|---|---|
| 完整 | 默认 | 全部动效 |
| 温和 | 系统开启"减少动态效果" | 开场改为 0.8 秒淡入淡出；背景流动降到三分之一速度，取消鼠标交互；出现动画只用淡入，没有位移、视差和缩放；没有自动横向滚动 |
| 轻量 | 实测前 60 帧平均低于 30fps，或 `deviceMemory` ≤ 4，或开启省流量（`saveData`） | HRIS 拓扑降到约 600 个点；Canvas 按 1 倍分辨率绘制；帧率封顶 30 |
| 关 | 访客在开关中选择 | 全部静止，直接显示最终状态 |

- 两条线的页脚都有「动效：完整 / 温和 / 关」开关。访客的选择写入 `localStorage`，优先于自动判断；读写失败时按自动判断执行。
- 档位判断集中在新增的 `src/scripts/motion/tier.ts`。现有的 `prefersMotion()` 调用点改为读取档位，`armOnScroll` 等工具在温和档下只做淡入，不再直接跳到最终状态。
- 只有浏览器不支持 Canvas 时，拓扑才退回静态 SVG。
- **可见度下限**：首屏背景动效的线条与点相对底色的对比度不低于 1.6:1。数值由单元测试按令牌计算并守住，避免再出现"调暗到看不见"。
- 页面不可见（`visibilitychange`）或滚出视口时暂停；帧率由现有的 `frame-cap.ts` 封顶。

### 7.4 工程要求

- 弹簧阻尼积分器、拓扑布局（治理前与治理后的目标点）、流式分块、档位判断都写成纯函数，用固定随机种子做确定性单元测试。
- 不新增运行时依赖：沿用 GSAP、原生 Canvas 2D 和 SVG。
- 动效不能让正文被遮挡超过 2.5 秒（沿用现有安全时限），文字始终存在于静态 HTML 中。
- 每页新增脚本有体积上限：AI 首屏不超过 12 KB（gzip），HRIS 拓扑不超过 10 KB（gzip），由测试检查构建产物。
